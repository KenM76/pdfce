# annot — provenance and attribution

Sixteen minimal PDFs for Pass 6.0 (annotation appearance **rendering**,
read-side; ISO 32000-1 §12.5, `docs/decisions/008`). Each file isolates
**one** claim from the appearance-display contract — the §12.5.5
placement algorithm from both directions, the §12.5.3 display flags, the
`/Popup` non-paint rule, R43 named-not-painted, `/AS` state selection,
and the X8 appearance-resource-scoping trap — so a failing test names the
clause it broke rather than reporting that "annotations are wrong".

## Source material and license (LEGAL.md §5)

**Nothing here derives from a third-party file.** These are `LEGAL.md`
§5 category (a): **wholly synthetic**, authored for this project,
generated byte by byte by a committed script
(`tools/gen-annot-fixtures.py`) with no PDF library behind it — so the
fixtures cannot inherit a bug (or a normalization) from the very code
they test, and no attribution is owed or claimed. Every file is a single
200×200-unit page with a classic §7.5.4 cross-reference table.

Every appearance stream fills its **entire `/BBox`** solid black, which
is what makes placement assertable from the raster alone: the painted
region on the page is exactly the image of the `/BBox` under the §12.5.5
transform, so "is the stamp in the right place?" reduces to a pixel
check. No embedded font programs are used except in
`ap-resources-own-font.pdf`, whose two fonts are the non-embedded
standard-14 faces Helvetica and Times-Roman (§9.6.2.2 permits omitting
`/Widths` and `/FontDescriptor` for the standard 14) — pdfce draws these
with its bundled substitute faces and the fixture asserts on *which*
substitute was chosen, not on glyph shapes.

## What each file pins

### Placement (§12.5.5), both directions

| File | `/BBox` | `/Matrix` | `/Rect` | Claim |
|---|---|---|---|---|
| `placement-identity.pdf` | `[0 0 20 20]` | identity | `[40 30 60 50]` | one-to-one map into a non-origin rect |
| `placement-nonorigin-bbox.pdf` | `[100 100 120 120]` | identity | `[0 0 40 40]` | step b translates a far-from-origin box onto the rect |
| `placement-bbox-larger.pdf` | `[0 0 80 80]` | identity | `[10 10 30 30]` | scaled DOWN to fit |
| `placement-bbox-smaller.pdf` | `[0 0 5 5]` | identity | `[0 0 200 200]` | scaled UP to fill |
| `placement-matrix-scale.pdf` | `[0 0 10 10]` | `[2 0 0 2 0 0]` | `[0 0 40 40]` | `/Matrix` applied ONCE (fit absorbs it) — the double-apply trap |
| `placement-matrix-rotate.pdf` | `[0 0 20 20]` | 90° | `[20 20 60 60]` | step a takes the axis-aligned bounds of the rotated box; no spill |
| `placement-inverted-rect.pdf` | `[0 0 20 20]` | identity | `[60 50 40 30]` | §7.9.5 corner normalization; no divide-by-negative |
| `placement-degenerate-bbox.pdf` | `[10 10 10 90]` | identity | `[0 0 40 40]` | zero-width box ⇒ singular fit matrix ⇒ **named refusal**, never a divide-by-zero (risk X2) |

### Flags + non-goals (§12.5.3, §12.5.6.14)

| File | Claim |
|---|---|
| `flags-hidden.pdf` | `/F 2` (Hidden): a full-page fill that must NOT appear, and is counted (R50) |
| `flags-noview.pdf` | `/F 32` (NoView): screen-suppressed on the screen render path, counted |
| `popup-not-painted.pdf` | a `/Popup` with a (malformed) full-page `/AP`: never page content (risk X4) |
| `no-ap-circle.pdf` | a `/Circle` with `/IC` and no `/AP`: R43 — pdfce synthesises nothing from `/IC` |

### Appearance-state selection (§12.5.5)

| File | Claim |
|---|---|
| `as-state-checkbox.pdf` | `/N` On/Off subdictionary, `/AS /On` → the On appearance is painted |
| `as-missing-state.pdf` | `/AS /Maybe` (absent state) → display nothing, counted, never guessed (NOTE 3) |

### Resource scoping (§8.10 / §7.8.3, risk X8)

| File | Claim |
|---|---|
| `ap-resources-own-font.pdf` | page `/F1` = Helvetica, appearance `/F1` = Times-Roman; the appearance must resolve `/F1` against its OWN `/Resources` — pinned via the substituted-font diagnostic |

### Demonstration

`demo-annotated.pdf` — one page combining a painted stamp (lower-left), a
Hidden full-page stamp, a no-`/AP` circle, and a `/Popup`. This is the
file the Pass 6.0 completion demonstration renders (with and without
`--no-annotations`) and lists with `list-annotations`.

## Regenerating

```
python tools/gen-annot-fixtures.py
```

The script is the single source of truth; do not hand-edit the `.pdf`
files. Deleting and regenerating them must be a byte-for-byte no-op
(the writer is deterministic).
