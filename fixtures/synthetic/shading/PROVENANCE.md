# shading — provenance and attribution

Single-page PDF fixtures pinning that **a shading and a flat fill of the same
authored `DeviceCMYK` ink render the same colour**. Generated by
`tools/gen-shading-ink-fixtures.py`; used by
`crates/pdfce-render/tests/shading_ink.rs`.

## Source material and license (LEGAL.md §5, project rule 7)

**Nothing here derives from a third-party file.** These are `LEGAL.md` §5
category (a): **wholly synthetic**, authored for this project, assembled byte
by byte from ISO 32000-1's own object syntax by a committed script. No
attribution is owed or claimed, and nothing was downloaded from anywhere.

**★ In particular, no byte of the licensed print-conformance suite is
reproduced here, and neither is its structure.** That suite is where the
operator *saw* the defect — a page whose shading boxes print a live shading
beside a reference image of what it should look like — but it is not
redistributable, it is not in this repository, and it is not present on a
fresh clone or on CI. These two files are the committed half of the evidence,
and they are deliberately **not** a reconstruction of that page: no reference
image, no four-up layout, a different colour, a different page size, and a
*constant* shading where the suite uses gradients.

The PDFs use a classic §7.5.4 cross-reference table with no object streams and
no compression anywhere, so a failing assertion can be diagnosed in a hex
editor and a fuzzer mutating one keeps producing something a parser engages
with.

## The two files

Both are 200 × 100 pt and draw the **same colour twice**: a flat filled
rectangle at (10, 20) 80 × 60, and an axial (`ShadingType 2`) shading clipped
to (110, 20) 80 × 60 whose `FunctionType 2` has `C0 == C1`.

| file | page group | what it pins |
|---|---|---|
| `shading-vs-fill-cmyk.pdf` | `/Group << /S /Transparency /CS /DeviceCMYK >>` | on a page that composites in **ink**, the two must be the same colour |
| `shading-vs-fill-rgb.pdf` | *(none)* | the **additive control** — they must match there too |

### ★ Why the shading is CONSTANT

A gradient cannot be compared against a flat fill without choosing a parametric
position and then arguing about whether the chosen pixel is really at `t = 0.5`.
A shading whose ramp is constant is the same colour **everywhere**, so any pixel
of it is comparable to any pixel of the fill, and the assertion needs no
geometry, no interpolation model and nothing remembered between runs. The
fixture is about *colour transport*, and the geometry is noise.

### ★★ Why the colour is `0.42 0.87 0.13 0.06` and not a primary

All four colorants are non-zero and the value is nowhere near a
`CMYK ↔ sRGB` fixed point. A round trip through sRGB moves it measurably —
**18 levels**, as the pre-fix A/B recorded. Pure cyan, or black, survives the
same round trip nearly intact and would have let the defect pass unnoticed;
a fixture that cannot fail is not a fixture.

### ★★★ Why the additive control is asserted at all

It passed before the fix and passes after, which makes it look like dead
weight. It is not: the additive page and the subtractive page are **different
code paths**, and without the control a future change that breaks the additive
one could hide behind the subtractive test staying green. The control's job is
to make that impossible, not to catch today's bug.

### What is deliberately NOT asserted

**That the two pages match each other.** A subtractive page converts out of ink
at the end; an additive one never entered ink. They are *required* to differ
wherever that conversion is not the identity. `shading_ink.rs` carries a third
test whose entire purpose is to stop somebody "tightening" the first two into a
cross-page equality that would be false for a correct renderer.

### What is NOT covered

**Mesh shadings** (types 4–7). `Shading::paint_cmyk` refuses non-analytic
geometry, so a mesh still bridges through sRGB and still disagrees with an
image of the same ink — a pre-existing, filed residual. When that is fixed, its
fixture belongs in this directory and its test in `shading_ink.rs`.

## Regenerating

```
python tools/gen-shading-ink-fixtures.py
```

The generator is the source of truth; the PDFs are committed so the test suite
does not require Python. Byte-for-byte reproducible — it takes no timestamp,
no random seed and no environment input.
